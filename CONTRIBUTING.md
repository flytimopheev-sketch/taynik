# Участие в проекте Тайник

Спасибо за интерес к проекту! Любой вклад приветствуется — от исправления
опечатки до новой функции.

## Быстрый старт

```bash
git clone https://github.com/flytimopheev-sketch/taynik.git
cd taynik
cargo build
cargo test
```

Требуется Rust (stable) и GTK4 ≥ 4.10. Все зависимости вендорены в `vendor/`,
поэтому сборка работает без доступа к сети.

## Обязательные проверки перед отправкой PR

```bash
cargo fmt --check          # форматирование кода
cargo clippy --all-targets # статический анализ (warnings не допускаются)
cargo test                 # модульные тесты
```

Все три проверки выполняются в CI
([`.github/workflows/ci.yml`](.github/workflows/ci.yml)); сборка RPM запускается
по тегу `v*`.

## Структура проекта

| Каталог | Назначение |
|---------|-----------|
| `src/db/` | Криптография, схема БД, репозиторий, импорт/экспорт |
| `src/models/` | Доменные модели: запись, генераторы, TOTP, аудит |
| `src/ui/` | GTK4-интерфейс: окна и диалоги |
| `packaging/` | RPM-спецификация, desktop-файл, AppStream-метаданные |
| `docs/` | Документация по архитектуре |
| `vendor/` | Вендоренные зависимости (обновляется через `cargo vendor`) |

Подробнее — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Как добавить зависимость

Проект собирается без сети, поэтому новую зависимость нужно завендорить:

```bash
cargo add <crate>
cargo vendor vendor
```

После этого обновите `Cargo.lock` и убедитесь, что `cargo build --offline`
по-прежнему работает. Вендоренные файлы не редактируются вручную.

## Соглашения по коду

- Форматирование — `rustfmt` (никаких ручных отступов).
- Имена, комментарии и сообщения об ошибках — на русском языке;
  идентификаторы в коде — на английском.
- Публичные функции документируются doc-комментарием `///`.
- Ошибки не проглатываются: не используйте `unwrap_or_default()` для
  операций, которые могут потерять данные, — возвращайте ошибку вызывающему.
- Криптографические изменения должны сопровождаться тестами с эталонными
  векторами (RFC 2202, RFC 4231, RFC 6238).

## Стиль коммитов

Короткие сообщения в императивном настроении, на русском или английском:

```
Исправлена смена мастер-пароля: данные перешифровываются новым ключом
Добавлен генератор парольных фраз
```

## Порядок работы

1. Откройте issue или пришлите PR с описанием изменения.
2. Сделайте изменения отдельной веткой от `main`.
3. Убедитесь, что `fmt`, `clippy` и `test` проходят.
4. Откройте Pull Request, опишите, что изменилось и почему.
